# v0.7.1 上传/艾特修复测试报告

## 修改范围
仅修改 `src/mention-page.js`、`src/mention-runner.js`、`src/renderer.js`、`src/index.html`，新增专项测试，沿用原应用 ID 和会话分区；其余账号、项目、参考图及下载模块不改变。

## 修复内容
- v0.7.0 错把 `DOM.setFileInputFiles` 的返回当“已上传”。现在拆为 **文件已选择 / 网页附件已确认 / 原生@已验证** 三个独立计数。
- 改为拦截 `Page.fileChooserOpened`，以这次用户可见上传入口真正触发的 `backendNodeId` 选择文件；仅在无歧义时回退图片上传 input。
- 上传后持续观察本页附件，不再固定等900ms就判断。未确认的标记待处理，不自动 @。
- 只在可定位到唯一名称的原生 @ 菜单项后点击，且确认出现有 `data-mention` 等明确标识的原生引用组件才计数。
- 登录会话分区、旧数据、提示词原文、手动多图拖拽、下载功能均保留。

## 仍需 Windows 用户真实网页测试
- 不同豆包账号/模型页面的上传控件差异；CDP文件选择是否触发真实上传；多个文件名显示与编辑器引用节点特征。
- 网站不显示文件名/原生引用标记时，程序会停在“待确认”，不能宣传100%自动成功。
- 用户需先在一个聊天中用1张A15图片测试，再增加到3、6张；观察聊天框是否真的出现附件并生成@。不要自动发送聊天。

## 非功能范围
- 不恢复无限画布，不接入私有豆包接口，不绕过认证/风控，不共享Cookie，未做 Themida 商业加壳，未配置私有 GitHub 自动更新通道。
