# 豆包创作舱 v0.8.0｜一键导入集成方案与验收报告

## 产品目标

**点击一次「⚡ 一键导入：提示词＋参考图＋@」**，从当前工作台选中的剧集/分段读取完整提示词，提取「需要参考图」栏目中的 A/AG/B/BL/C/E 编号，精确绑定本地图片，逐张送入当前豆包账号的官方网页上传控件，确认后填写完整原文与「图1=A15」形式的映射表；网页有可用原生 @ 图片菜单时进一步尝试并验证。**绝不自动发送**。

本版本基于 GitHub 分支 `release/doubao-browser-oneclick-at-v0.7.1`，应用身份保持 `com.manju.doubao.creativehub`、包名保持 `doubao-creative-hub`、会话分区保持 `persist:doubao_<账号ID>`；所有已登录账号、剧集、参考图目录和下载功能均保留。**不恢复画布。**

## 原因与方案选型

旧版 v0.7.0/0.7.1 通过 CDP 找到文件输入框、写入路径，但在真实豆包页面上被用户证实没有上传成功，依然误导为“文件已选择”。

独立 Edge 插件 v0.1 使用 `File` + `DataTransfer` + 官方 `input/change` 事件，已完成独立网页测试。v0.8.0 复用这一机制，将工作台识别的本地字节以受限的主进程→当前豆包网页调用传递，而不是让用户再打开浏览器插件选择文件夹。

**版权与安全：** 原始独立插件由当前项目制作；可以维护和复用自己的原版代码。不读取浏览器 Cookie、卡密、密码，不调用未公开的视频生成 API，不绕过官网权限与登录流程。发送按钮始终由用户操作。

## 技术分层

| 模块 | 职责 | 来源 |
|---|---|---|
| `src/import-core.js` | 严格从「需要参考图」栏目识别编号；生成图号映射 | 独立插件 v0.1 |
| `src/import-engine.js` | 校验本地图片、管理任务状态、逐张发送和超时、取消、@ 尝试 | 新增 |
| `src/import-page.js` | 豆包浏览器页内的 File/DataTransfer/input/change、编辑器探测、全文填写回读 | 独立插件方案改造 |
| `src/main.js` | 仅操作当前 `WebContentsView`、当前账号和当前段，受限 IPC | 增量 |
| `src/preload.js` | 安全桥接，避免渲染进程任意读取文件 | 增量 |
| `src/renderer.js`、`src/index.html`、`src/style.css` | 一键导入、预检、逐张状态、人工确认和取消 | 增量 |

## 精确执行状态

1. **预检**：读取当前段原文；若缺图、同编号有多个未指定版本、图片不支持或超过9张，则不进入网页操作。
2. **已有草稿保护**：豆包输入框已有不同内容时，由用户确认覆盖，取消则保留原内容。
3. **现有附件保护**：有不属于本段或顺序不符的附件时暂停，避免“图1”映射错位。
4. **逐张上传**：从本地读取 `A15.png` 等真实文件，调用当前页官方文件控件 `DataTransfer + input/change`；文件选择成功只显示「文件已选择」。
5. **网页确认**：轮询网页可见附件文件名，连续两次稳定且无上传进度才记为 `uploaded`。
6. **图片仅有缩略图时**：弹出「确认当前图片」，由用户在浏览器查看后继续；手动确认与自动核验的统计必须分开。
7. **不可确认时**：立即停止，不继续上传剩余图片，不自动修改提示词，避免编号混乱。
8. **提示词写入**：当所有图片都得到网页确认或人工确认后，完整保留本段原文，追加图号/参考图文件名映射；回读一致才显示成功。
9. **原生 @**：只在豆包官方网页有唯一、可核对的 @ 菜单项时尝试；检测到真正原生引用标记并与编号匹配才记「原生@已验证」。无 @ 菜单则保留图号表，绝不显示假@成功。
10. **账户与导航**：切换账号、当前段、聊天 URL 或重新加载网页时，停止任务。手动发送始终留给用户。

## 用户正常使用流程

在软件右侧选择集、段 → 确认提示词和参考图目录 → 在豆包内打开该账号的聊天 → 点击 **「⚡ 一键导入：提示词＋参考图＋@」** → 查看每张状态 → 如有提示，核对新缩略图并点「确认当前图片」 → 检查输入框和附件 → 自己点豆包官方「发送」。

## 测试记录与证据边界

- Node.js `npm run check`：44项自动测试通过，覆盖编号误配、缺图、重号、超限、不同草稿保护、应用身份/登录分区稳定性。
- 离线 Chromium + Playwright：6张图片依次通过 `File/DataTransfer/change` 进入**模拟**附件区，完整提示词与映射表逐字回读一致，无 JS 错误，且未点发送。
- 与真实豆包网页的端到端上传/原生 @：本环境没有用户的登录会话，**尚未真实验收**。因此只能称为「集成测试版」，不是已证明兼容当前豆包所有网页模式的正式版。
- 商业 Themida/VMProtect 加壳、Windows Authenticode 签名：**未完成**。生产构建仍有普通 JS 混淆与 Electron Fuses/ASAR 加固，不冒充商业加壳。

## 异常排查

如果网页没有图片：先确认当前豆包聊天模式是否开放上传；点开「＋」上传菜单后重试；如仍失败，看右侧状态卡片中是「网页未找到上传控件」还是「文件已选但网页无附件」。这两个失败点需要分别适配，不能用“已提交”掩盖。若有缩略图却缺文件名，可手动核对再继续。不要在日志中复制 Cookie、账号密码或完整敏感剧本。

## 回退方式

源码分支与 v0.7.1 完全分离，旧 Release 原样保留。采用原 `appId` 的 NSIS 安装包覆盖可保留用户数据（需 Windows 真机复核），软件使用前建议导出项目备份。出现异常可重新安装 v0.7.1，不主动删除 `userData` 或账号浏览器分区。
