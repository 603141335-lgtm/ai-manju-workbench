# 豆包创作舱 v0.9.5 公开分发版｜完整开发方案

> 基于现有 v0.9.4 实际源码增量实现，不替换作者原工作版、不读取旧工作区。状态：基础功能框架已经写入独立 GitHub 分支；正式远程公告需要配置公网 HTTPS JSON，豆包网页真实多账号场景还需 Windows 真机验收。

## 1. 产品定位和分发原则

“本地创作 + 云端公开通知”，不是云端工作台。25 个账号位置、剧集、完整提示词、参考图、音色、下载、尾帧、备用浏览器继续本地运行。每位新用户第一次打开的是空白项目与 25 个未登录的账号位置，必须自己登录。

公开版的 Windows 安装器/卸载列表/快捷方式显示“豆包创作舱（公开版）”，避免和作者工作版的安装目录、快捷方式重名；软件内部品牌仍为“豆包创作舱”。

公开版改用独立应用标识 com.manju.doubao.creativehub.public；私有用户目录为 %APPDATA%\DoubaoCreativeHubPublic；成品下载目录为当前用户 Downloads\豆包创作舱-公开版。不会自动导入旧工作版数据。公开版未来更新应继续沿用这个公开目录，以保留每位客户自己的登录和项目数据。

安装包构建只收录明确的程序源文件、应用配置、图标与必要 FFmpeg 运行资源。不得把本人的 config.json、workspace.json、Cookies、User Data、AppData、素材、私人备份或环境变量文件打入 EXE；不得把作者完整已安装目录压缩后转发。

## 2. 联网广告和社群中心

界面右上角新增“社群·公告”，提供版本信息、官方活动通知、微信群二维码、微信号与 QQ 群链接。公告可远程修改，不干扰豆包输入和视频生成。只有新公告或版本时才显示圆点。

管理员维护一份公开 HTTPS JSON（参考 docs/public-announcement.example.json），包括：
- release：version/title/notes/url，控制最新版本文案及下载入口
- notice：id/title/body/showHint，控制活动公告和右上角轻提示
- community：title/description/wechat/qqUrl/qrUrl，控制社群和二维码
- updatedAt：管理端可修改的时间

客户端首次打包时通过 DOUBAO_NOTICE_URL 注入固定的 HTTPS 地址；日后修改同一 JSON 内容不需要重新打包。第一次配置域名需要打包一次；更换入口地址也需打包，除非预先做域名重定向架构。公告内容和二维码都为空时默认显示优雅占位内容。

客户端启动时先读本地公告缓存，随后联网读取，后续每小时刷新，也可手动刷新。最长等待6秒，响应不超过64KB。验证 JSON、限制文字长度、外部地址只能是 HTTPS，不执行服务端 HTML/JavaScript，不开放对任意本地文件的操作权限。下载入口只打开用户系统浏览器中的 HTTPS URL，不静默执行安装包。

断网：显示已缓存的公告或“暂未配置”；本地创作和已有素材不受影响。豆包官网视频生成仍需要网络。公告服务不会上传 Cookie、账号、剧本、提示词、素材路径或个人文件；但一般 HTTPS 访问仍会向运营方服务器暴露网络 IP 等连接元数据。

可选“showHint=true”开启一次右上角小提示；用户关闭后按公告 ID 在当前电脑记录，不出现强制倒计时和占满屏幕的开屏广告。

## 3. 内存优化与多任务安全

已有25个账号“位置”，只有选择过的账号才会建立浏览器视图。内存主要来自 Electron 主/渲染/GPU 进程以及豆包网页的图片、视频、会话和渲染开销。仅看单个 EXE 的任务管理器内存不可与 WebView2 总进程直接比较。

公开版提供三种模式：省内存 1 个活跃浏览器视图；均衡 2 个（默认）；多任务 3 个。超过上限时只考虑释放最久未使用的后台视图，且必须先征求用户确认。默认按钮为“保留后台页面”。未经明确确认绝不自动关闭正在隐藏的页面，因为豆包生成或上传是否活跃无法可靠由客户端统一检测。已释放的视图下次切回会重新载入，但对应登录分区保留。

性能界面显示浏览器视图数与 Electron 进程工作集 MB 估算。后续实测若必要，再做大图按需生成缩略图、长剧集虚拟化、缓存限制等性能升级；禁止用强制 reload、删除 Cookie、盲目杀浏览器进程换取“看似省内存”。

验收场景：冷启动空白工作区；浏览 1、2、3 个账号；各段9张参考图；多账号切换；正在生成时拒绝释放；主动确认释放后重新登录状态是否保留；长期运行观察工作集趋势。任何“减少百分之多少”的宣传必须由同设备同任务实测取得。

## 4. 首次启动与隐私

- 在全新 Windows 系统账户下安装：无用户提示词、无本人的豆包登录、无作者微信号、无导入过的剧集，也没有本人的参考图绝对路径。
- 首次自动创建随机账号 UUID、5组25个空白名称、一个空段落及空白工作区；cookie 仅在使用者随后自己登录时产生。
- 备份恢复只由用户主动操作，绝不自动搜索作者旧版目录。
- 工作版与公开版拥有不同 App ID、userData 和下载总目录，不能共享已有登录 session。
- Windows 卸载默认不主动清除用户数据，保护使用者自己的作品；若以后增加“清除所有本地个人信息”需独立危险操作并二次确认。
- 保护用户数据不等于防逆向。公开安装包中的 JavaScript 和静态配置仍可能被分析，不应硬编码付费口令、后台密钥或私人登录信息。

## 5. 版本发布方案（不做自动安装）

用户在“社群·公告”中查看云端 release.version 与客户端实际版本对比。只有云端版本更高、且存在合法 HTTPS release.url 时才显示“下载最新版本”。用户点击后交给系统浏览器；用户自行确认下载安装。后续若需完整一键升级，再独立开发自动更新服务。

源代码保存在私有 GitHub。正式对外分发的 EXE 需要公共可访问的托管站点（例如可信对象存储/CDN）。私有仓库 Release 适合内部验收，但不能要求所有普通用户登录你的 GitHub。建议给最终安装包签名，并发布 SHA256 校验值。

## 6. 开发模块与本次交付范围

A. 数据隔离：src/main.js、src/store.js、package.json、release-build.json；独立数据目录和 App ID，空白用户首次初始化。

B. 云端公告：src/notice-service.js、src/public-config.json、scripts/prepare-public-notice.js、docs/public-announcement.example.json；只读、安全过滤、超时限制、离线缓存、文本/二维码/版本链接。

C. 社群 UI：src/index.html、src/renderer.js、src/style.css、src/preload.js；右上角入口、公告轻提示、最新版本按钮、QQ群和二维码显示。

D. 内存：src/main.js；1/2/3模式，主动确认后才释放后台视图；性能统计；默认2。

E. 自动测试：tests/v095-public.test.js；校验公开版目录、安装清单、链接清理、版本号和后台释放确认机制。

不包含：真实公告域名部署、你的微信二维码与群链接、广告编辑网页后台、精确豆包后台生成状态识别、Windows 真机登录验证、代码签名。

## 7. 接入真实宣传时的步骤

1. 准备稳定的公网 HTTPS JSON 地址，例如 https://example.com/doubao/notice.json。
2. 把 docs/public-announcement.example.json 的 release、notice、community 内容替换为真实信息；二维码上传后填写 HTTPS qrUrl。
3. 打包时设置 DOUBAO_NOTICE_URL 为该 JSON 地址，然后重新生成一次公开版 EXE。
4. 以后你只改服务器 JSON，用户启动或点击刷新后即可看到新公告与群信息，软件自身无需升级。
5. 正式对外推广前用全新 Windows 用户账户测试：无作者登录信息、无个人素材、没有旧工作版的下载记录；并验证断网、二维码、安全外链、内存确认和真实豆包生成不中断。

说明：若安装包没有设置 DOUBAO_NOTICE_URL，社群面板已存在，但只显示占位内容。当前并未代替你创建或收费购买任何公网服务器。
