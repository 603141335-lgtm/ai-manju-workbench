# 豆包创作舱 v0.9.7｜视频识别、API接口、联网公告优化版

在 v0.9.6 公开版基础上更新，保留当前公开版 App ID 和 Windows 用户目录，所以老用户升级后保留自己的豆包登录、剧本和素材。原作者的 v0.9.4 工作版仍是完全独立的程序，新安装用户初始拥有25个空白账号位。

## 1. 修复用户截图里的视频模式误判

截图一实际上已打开豆包「视频生成」，顶部蓝色选中标签带关闭叉，模型显示「Seedance 2.0 Fast」，视频参数显示「自动 · 15s」。旧检测器把这些选中标签当成未识别，从而错误阻断导入。

新检测器只读检查：
- 当前可见的视频输入框提示文字，如「描述你想要的视频」
- 带关闭叉号的已选中视频模式标签
- aria-pressed、aria-selected、data-state=active等实际选中状态
- Seedance 2.0 Fast、16:9、15秒分别显示单独识别结果

只要视频输入框或选中标签已识别，就可以进行原本的导入预检，不再因为没识别到比例/模型/时长而整体拦截。对于截图里的「自动 · 15s」，由于无法确认16:9，软件必须提示用户自行核对，不能虚报已经选中横屏。旧探测代码会尝试乱点参数按钮，新版本改为只读扫描，不会擅自切换。

截图二是聊天输入框，有「视频生成」菜单选项但不代表选中。新检测器不会把普通菜单项误认为已选视频模式。

网页底部提供「重查视频模式」和「人工确认模式」。人工确认前用户需要在原生窗口确认当前确实进入视频生成；只对当前账号当前页面生效30分钟，重新导航/加载即失效，不会绕过真实附件/蓝色@核对，不会自动提交生成任务。

## 2. 左上角API接口

在品牌文字左边增加小型「API 接口」按钮，点击展开本地 API 配置窗口。支持 OpenAI、DeepSeek、火山方舟以及兼容 OpenAI Chat Completions API 的自定义服务。

可填写公网 HTTPS 基础地址、模型ID、API Key。密钥使用 Electron 的 Windows safeStorage 加密保存到当前用户目录 api-settings.json，软件界面只能显示是否保存，不向普通前端回传明文，不打包到公开安装程序。Windows无法提供安全加密功能时拒绝以明文存储。

提供两个真实功能：
- 测试连接：尝试 GET /models，某些中转服务可能不支持该查询，失败不一定表示模型无法调用。
- 手动测试文字：调用 /chat/completions，响应长度受限、最多160输出Token，需要用户自己输入文本并点击，可能产生少量Token费用。

不会自动读取上传正在编辑的漫剧提示词、参考图、Cookie、视频或任何本地工作区文件。当前是文本模型API设置与手动对话测试入口，不代表已经对接豆包视频生成 API，也不替代豆包网页会员。

## 3. 内存模式

用户明确不需要三档内存模式。删除顶栏「性能」和模式设置窗口。保留不损失图像画质的192px参考图本地缓存。后台网页不会在切换账号时自动关闭。「更多 → 清理闲置后台网页」提供单独操作，需要用户手动确认并避免释放正在下载的网页。

## 4. 联网社群与老用户同步

v0.9.6 安装版大约每小时刷新公告；v0.9.7 调整为每5分钟刷新一次，启动时和点击「刷新公告」也会请求更新。它属于轮询，非WebSocket的秒级主动推送。

旧用户可在公告服务器上线之后看到远程内容，前提是软件里内置的固定 URL 能够访问。预留URL：
https://raw.githubusercontent.com/603141335-lgtm/doubao-creative-hub-notices/main/notice.json

该公开公告仓库目前没有创建，因此修改自己电脑上的宣传信息不会影响老用户。请在这个地址创建公开仓库并在 main 分支加入 notice.json 文件，按照 docs/public-announcement.example.json 填写微信号、二维码、群链接、版本公告和下载地址。完成后，用户下次轮询或手动刷新即可看到修改；不必重新下载客户端。

## 5. 分发与验证

Windows安装包文件名：Doubao-Creative-Hub-Public-Setup-v0.9.7-x64.exe
独立发布标签：doubao-public-v0.9.7
运行数据目录：%APPDATA%\DoubaoCreativeHubPublic

自动测试包含截图文案模拟DOM、视频选中与普通聊天区分、16:9未知却不阻止导入、API Key不以明文存储、API HTTPS和内网地址检查、授权后手动 API 文字调用，以及移除内存档位界面但保留清理按钮。

正式公开分发之前仍需在 Windows 真机登录豆包，检查模式、15秒、参考图上传和蓝色@；模拟 DOM 检查不等于真实豆包网页始终可用。API 服务商模型和调用额度需要用户自己提供，无法保证所有自定义中转支持 GET /models。公开视频下载页面也需要另行公开发布，GitHub 私有仓库 Release 无法供没有权限的外部用户直接下载。

## 6. 后续建议（未额外开发）

完成版本后建议先小范围给几个真实使用者测试，再考虑：
1. API模型调用费用统计，按账号/模型汇总。
2. 视频任务段落映射与下载对账，避免多个账号同时生成时错绑尾帧。
3. 更轻量的运营公告后台，不必手工编辑 JSON，支持定时发布和撤回。

以上为后续建议，不影响本版既有功能。
