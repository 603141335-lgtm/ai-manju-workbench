# 豆包创作舱 v0.9.2｜人物图片与音频绑定·开发及验收说明

## 功能范围

新增人物参考图 Axx → 本地音频 WAV/MP3 的绑定。一个人物可保存多个声音样本，每个角色指定一个默认样本；当本段参考图包含该角色时，点击原「一键导入」会在同一次操作中先上传图片，再尝试上传对应音频，并把人物-图片-音频编号关系统一写到提示词顶部。**这是音色参考绑定，不是已验证的强制指定人物读出音频内容，也不保证口型完全一致。**

保持原 `com.manju.doubao.creativehub` 应用 ID、Electron WebContentsView 账号隔离、剧集、画风、原始提示词、尾帧和图片上传模块不变；无画布。

## 用户操作

1. 右侧选择集和段，「参考图片」区中有 `A15` 等人物图号。
2. 点「🎙 人物声音绑定 → ＋ 绑定人物声音」。
3. 选择 A15，填写「李小（清亮女声）」等人物声音标签，选择 WAV/MP3。单个角色可添加多段样本，点击 ▶ 试听、设为默认、× 解除绑定。
4. 保存到电脑本地 `voice-bindings.json`，不会修改原文件，也不写入豆包账号分区。
5. 点击旧有「一键导入」，软件根据本段实际参考图编号自动挑选对应的默认声音；先处理图片附件，再尝试通过豆包当前聊天页的音频文件上传控件提交选中音频。只有官方网页连续两次显示音频文件名且无上传进度，才判定音频已确认。
6. 在「需要参考图」下依次呈现图片编号、音频编号和绑定关系，例如：`图1 = A15`；`音频1 = A15（李小声音：A15_声音.wav）`；`图1（A15）中的人物使用音频1作为声音/音色参考`。
7. 只在豆包真实 @ 菜单提供对应唯一音频时，尝试在该音频说明行插入原生 @，并校验确实出现该行原生富文本引用；否则保留对应文字并显示「音频@未验证」，**不能把纯文本当蓝色引用**。
8. 不触发发送；用户检查结果后自己发送。

## 主要限制与安全性

- Seedance 2.0 官方参考约束：每个音频 WAV/MP3 长度 2—15 秒，最多3段音频、音频总时长最多15秒，每段文件不超过15MB；当前工作台按该版本做预检。不同模型（例如2.5）可单独增加能力适配，不能直接把2.5限制混用于2.0。
- 官方模型支持参考音频不等于任何豆包网页版聊天模式都开放音频上传控件。尤其普通「对话」模式与「视频生成」入口可能不同。**音频上传和原生 @ 在已登录豆包官网当前界面仍需实测。** 检测不到音频上传控件就停止，提示原因；已上传的图片仍留在网页，原始提示词不会被修改。
- 不能保证生成模型严格保持音色、逐字复述音频或完全对口型；提示词指定仅是参考要求。
- 不使用破解、不调用内部上传接口，不保存密码/Cookie；绝不自动发送。
- 用户应使用自己有权使用的配音、合成声音或已授权的音色。
- 无论检测到多少绑定样本，本段只选每个角色一个默认样本；如果总音频上限超过3段/15秒则预检失败，提示改选或合并，不偷偷丢弃声音。
- 数据文件 `voice-bindings.json` 放在原用户数据目录；Windows 覆盖安装不会主动删除。建议升级前同目录备份原 `workspace.json`、`voice-bindings.json`。

## 代码位置

- `src/voice-bindings.js`：本地持久化、文件时长检查、默认音色、图片到音频关联计划。
- `src/voice-page.js`：仅在可信豆包聊天页操作音频文件输入控件、观察附件状态；不读取登录凭据。
- `src/main.js`：受限 Electron IPC，系统文件选择、试听、绑定、删除。
- `src/import-engine.js`：一键导入新增音频预检和上传步骤，失败不冒充成功；与现有图片、内联@链路协同。
- `src/import-core.js`：顶部图号映射后增加音频映射，原始分镜文本保留。
- `src/renderer.js`、`src/index.html`、`src/style.css`：右侧绑定区和声音管理交互。
- `tests/voice_bindings_v092.test.js`：持久化、角色选择、音频限制、提示词编排、桥接契约。

## 验收边界

目前通过本地 Node 测试与 FFmpeg 真实音频时长读取。**没有使用用户的豆包会员登录会话运行网站端到端测试**。Windows 安装程序构建成功也不等于网页音频上传成功。首次实机测试建议只绑定 A15 的一段3秒 WAV，点击一键导入后确认豆包有真实音频附件，再测原生 @，最后测两人物音频。如果豆包不支持音频上传，应在状态区显示失败原因而不是虚假完成。
