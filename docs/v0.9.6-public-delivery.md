# 豆包创作舱 v0.9.6｜公开分享版最终优化与交付方案

## 一、目标
基于 v0.9.4 完整功能创建独立公开版，不改变本人长期使用的旧工作台。公开版从干净的25个未登录豆包账号位、空白项目开始；云端只负责社群公告、最新版本下载提示和二维码，不读取任何用户素材或登录信息。性能默认均衡、可主动清理后台页面，参考图缩略图缓存减少界面解码负担。

## 二、隐私和首次启动
- 软件内部名称维持「豆包创作舱」，Windows 安装/卸载显示「豆包创作舱（公开版）」。
- Windows App ID：com.manju.doubao.creativehub.public。
- 运行数据目录：%APPDATA%\DoubaoCreativeHubPublic，独立于旧工作版；下载默认到 Downloads\豆包创作舱-公开版。
- 初始配置：5组25个空账号位、随机 UUID、手动进度0、空白漫剧项目、无参考图文件夹和音色绑定；用户首次登录后 Cookie 仅保存在自己的Windows用户目录。
- 安装包不包含旧 Cookie、用户工作区、个人资料、微信二维码、真实剧集、电脑上的素材路径；还在文件打包清单中排除意外放入 src 的个人数据库和配置。
- 公开版今后升级不应更换 App ID 或用户数据目录，保留新用户自己的工作历史；「不带作者数据」与「每次启动清空」完全不同。
- 在你的同一台电脑测试也不会自动读取旧工作版。注意不要把个人安装目录或整个 AppData 文件夹压缩给他人，只发布 CI 编译的安装包。

## 三、联网社群和宣传
- 右上角「社群·公告」模块包含：官方公告、最新版本检测与浏览器下载链接、微信号、QQ群链接、二维码。
- 界面通过安全的本地 IPC 读取公共 HTTPS JSON，不通过第三方网页直接执行宣传内容，限制请求大小64KB、超时与文本字段长度；下载按钮要求真实用户主动点击。
- 首次显示上次缓存，之后后台更新；没有公网服务时主软件正常使用、公告显示未上线状态。网络请求会向公告服务提供方透露常规 IP 等连接元数据，但软件不会发送 Cookie、登录口令、提示词、图片、音频、任务记录。
- 为解决“以后才修改宣传信息、现在先发安装包”的问题，v0.9.6 预留一个固定、尚未开通的公开内容地址：
  https://raw.githubusercontent.com/603141335-lgtm/doubao-creative-hub-notices/main/notice.json
- **注意：上述公告仓库尚未创建，地址目前可能返回404。** 以后只需创建同名公开仓库，在 main 分支增加 notice.json，再维护公告文字及二维码链接，就能让已安装的 v0.9.6 用户看到新内容，而不需要重新安装客户端。
- 现有私有软件源码仓库保持私有，公开公告仓库只放公告 JSON 和公开二维码等运营资料，切勿加入个人剧本、软件源码或账号隐私。
- 如果用户主要在国内，长期建议把相同 JSON 放到国内可访问的 CDN/对象存储，并在未来新版本切换地址，或部署稳定自定义域名。不能保证 GitHub Raw 在所有网络下都能访问。
- 公告文件示例：docs/public-announcement.example.json。字段有 release.version/title/notes/url、notice.id/title/body/showHint、community.title/description/wechat/qqUrl/qrUrl、updatedAt。
- 后续真正“管理后台”可采用可视化编辑 JSON，带登录鉴权和发布审核；此版本只交付安全的读取框架和 JSON 样例，不含登录后台或已上线的运营服务。

## 四、低内存但不破坏生成
- 默认「均衡」目标最多2个保留网页；省内存1、多任务3。25个账号位置不会在启动时同时加载25个网页。
- 账号切换不再触发后台网页清理弹窗，也绝不自动杀掉正在生成中的网页。
- 性能面板新增「保护当前账号」，受到保护的账号不会被手动内存清理选中。
- 点击「检查并释放闲置后台网页」时，程序先排除当前账号、受保护账号、正在下载的账号，列出剩余候选，必须再次点击确认才会释放；默认取消。
- **官方豆包的云端生成任务无法通过本软件可靠识别**，所以释放前需要用户人工检查正在生成的账号，不能承诺完全不受影响。
- 参考图预览使用 Electron Windows 原生 createThumbnailFromPath 生成192px PNG 本地缓存；上传、拖拽、复制源文件仍使用高清原图路径。缩略图缓存放在当前用户私有目录，并有最多500项的简单清理规则。生成失败时安全回退原图显示。
- 性能面板 MB 为 Electron 相关进程的工作集估算，并非完整 Windows 任务管理器综合内存统计。没有实测证据时，不承诺减少固定百分比。
- 不使用可能导致网页崩溃的全局内存硬限制、强制刷新或删 Cookie 方式。

## 五、版本发布
- 客户端内显示真实版本号，并根据公告的 release.version 与当前版本比较，只在确实有新版本且配置了HTTPS下载地址时显示下载按钮。
- 此版不强制自动下载和安装，不会影响本地未保存内容；用户主动用浏览器打开下载链接。
- CI Windows NSIS 构建产物固定为 Doubao-Creative-Hub-Public-Setup-v0.9.6-x64.exe。
- GitHub 私有 Release 标签为 doubao-public-v0.9.6；发布校验强制确认附带 EXE、SHA256SUMS.txt、blockmap，缺少时构建报错，避免上一版引用旧 v0.9.4 安装文件名造成发布页无附件。
- 私有 Release 的下载仅供登录授权账号验收。面向普通用户发布需要另行提供公开的安装包下载站；不得直接公开整个源代码仓库。

## 六、研发文件与验收
- 新增 src/thumbnail-cache.js：Windows 缩略图缓存，绝不改动原图。
- 修改 src/main.js：全新的公开版运行环境；主动清理后台页面；手动保护账号；下载中页面排除释放；缩略图文件预览 URL。
- 修改 src/index.html、src/renderer.js、src/preload.js：轻量社群中心、性能设置、保护当前账号和手动清理按钮。
- 修改 scripts/prepare-public-notice.js：预留未来公共公告 URL，允许构建时 DOUBAO_NOTICE_URL 覆盖。
- 修改 package.json、.github/workflows/build-windows.yml：0.9.6 专用的构建、测试、发布路径。
- 自动测试涵盖旧版25账号和网页、公开版数据隔离、真实尾帧模块、缩略图失效/命中/原文件不变、模式切换不自动清理、公告安全输入和版本号判断。
- **正式用户验收还需**：在一台新 Windows 账户安装，确认原作者的所有登录和素材都不存在；真实登录两个豆包账号并生成视频；多账号后台生成时检查不丢任务；打开一段9图，观察新缩略图加载与原图上传的正确性；在网络不通时验证公告不会影响主要工作台。

## 七、你的后续运营步骤
1. 先下载私有 GitHub Release 的 v0.9.6 EXE，在全新 Windows 账户测试。
2. 准备公开可访问的安装包下载页面，以后把 release.url 填进去。
3. 以后开通上述独立公告仓库（或者与之对应的公开 HTTPS 路由），用 docs/public-announcement.example.json 作初始 notice.json。
4. 上传微信/社群二维码并填写 qqUrl、qrUrl，文字和版本可以随时更新。客户端大约每小时自动刷新，也可以在“社群·公告”里点刷新。
5. 有新版本时更新 release.version/title/notes/url；现有用户看到提醒，再自行下载安装。
6. 若未来需要按用户分组投放、定时广告、付费 Skill 面板，可再加认证后台；不需要提前破坏本地工作台的稳定性。

## 八、已知限制
- 本次实现为**公开版稳定框架和安装包**，不等于部署了真实云端广告服务、运营后台。
- 不能仅凭静态代码测试保证豆包网页版自动上传、原生@和多任务生成在未来每个网页版本中都正常，需要 Windows 登录后手动验收。
- GitHub Raw 作为预留网址，国内部分网络可能不可达；后续建议正式运营时使用适当的国内可访问 HTTPS 域名。
