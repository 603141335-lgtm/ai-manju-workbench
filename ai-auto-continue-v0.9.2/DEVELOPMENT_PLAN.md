# AI自动续聊助手 v0.9.2｜界面精简与任务切换优化方案

版本基线：v0.9.1 轻简版  
本次性质：界面与任务选择交互优化，不重写自动续聊引擎  
核心目标：去掉顶部批量控制栏；四个平台状态卡改为方形；卡片点击即切换到对应任务；任务设置重新排版；最多同时运行 3 个任务。

---

## 一、需求确认与本次范围

本次按以下口径实施：

1. **彻底删除最上方的任务控制条**：删除“全部开始、全部新任务、全部暂停、继续全部”以及这整条批量任务控制区域。品牌标题和右上角的数据管理入口保留。
2. **同时运行上限固定为 3 个任务**：不再在顶部显示并发下拉框。运行调度器内部固定 `MAX_CONCURRENT = 3`。已保存的任务可以多于 3 个，但同一时刻最多 3 个任务运行；其余任务显示等待状态，空位释放后按启动顺序进入运行。
3. **四个平台状态卡改为方形卡片**：ChatGPT、Gemini、豆包、DeepSeek 各一张主卡，桌面优先 2×2 或 4 列方形布局，窄屏 2 列，极窄屏 1 列。卡片不再横向拉成长条。
4. **每张平台卡只保留四个运行操作**：开始、暂停、继续、重新。按钮按状态启用/禁用，不显示“全部开始”等全局动作。
5. **新任务不放在平台卡上**：在下方“任务设置”区域增加小方形任务选择块，已有任务各占一个小方块，最后一个固定为“＋ 新任务”。点击后创建新任务并加入列表。
6. **平台卡可点击**：点击 ChatGPT 或豆包等平台卡，自动切换到该平台当前正在运行的任务；若该平台没有运行中的任务，则切换到最近使用或最近暂停的任务。下方任务设置、进度、已保存内容和运行日志随之切换。
7. **运行窗口、已保存任务内容、运行日志的版式不重做**：保留现有模块的布局与功能，仅让它们读取当前选中任务的数据。
8. **任务设置重新分组排版**：减少同时出现的输入项，按“任务选择 → 基础设置 → 模型 → 创作指令 → 图片 → 其他设置”排列。
9. **保留 v0.9.1 已有功能**：模型列表检测、模型偏好、图片附件、双窗口/多任务实例、自动保存、暂停恢复、从头重跑归档、导出备份、历史记录；不恢复 Skill 功能。

## 二、当前 v0.9.1 源码问题定位

已检查 `dashboard.html`、`dashboard.js` 和 `style.css`：

### 1. 顶部控制条占据空间且重复

`dashboard.html` 中存在 `.commandbar`，包含 `startAll`、`pauseAll`、`resumeAll`、`newAll` 和 `concurrencyLimit`。这正是用户要求删除的最上方整条控制台。删除后，相关按钮绑定和不再使用的批量控制函数也应一并清理，避免留下无效事件。

### 2. 平台卡点击没有绑定选择事件

`renderCards()` 会生成 `.platform-group` 和 `.instance-card`，但卡片本身没有 `click` 事件；目前只有卡片里的“设置”按钮会调用 `choosePlatform(i)`。因此点击平台卡片主体不会切换任务，这是用户反馈“点击 GPT / 豆包没反应”的直接原因。

### 3. 当前任务实例数量写死为 A / B

`createInstance()` 固定创建 `${platform}-B`，如果 B 已存在就拒绝新增。`ids()` 也只枚举 A / B。新版任务设置中的“＋ 新任务”需要支持动态任务实例 ID，不能继续依赖固定 A/B 两个槽位。

### 4. 并发上限仍为可变配置

当前 `concurrencyLimit` 默认值为 2，顶部提供 2/3/4 选项。新版要移除可见设置，并把调度上限固定为 3；所有启动入口必须统一经过并发调度器，避免某个按钮绕过上限。

### 5. 任务编辑区缺少清晰层级

目前基础信息、模型、指令、图片、窗口绑定、模型锁定、聊天方式和高级选择器集中在同一块编辑区。新版需要分成少量清晰区块，并将低频设置收进折叠区。

### 平台卡片尺寸与布局

- 桌面宽屏：四张方形平台卡优先 4 列；如果可用宽度不足，自动切换为 2×2。
- 平板：2 列。
- 手机窄屏：2 列；屏幕特别窄时 1 列。
- 卡片使用固定比例 `aspect-ratio: 1 / 1`，内部内容用纵向 Flex/Grid 排列；卡片高度随宽度变化，不再出现很宽很扁的长方形。
- 卡片内容仅保留：平台图标/名称、状态、当前任务名称、进度、四个操作按钮。
- 卡片整体可点击，按钮点击必须 `stopPropagation()`，防止点击“暂停”时又触发卡片切换。

## 四、平台卡片四个按钮的行为

每张卡固定显示四个操作，采用 2×2 排列：

| 按钮 | 行为 | 保护规则 |
|---|---|---|
| 开始 | 启动当前选中的任务 | 任务未开始时从第一步开始；已完成任务不直接覆盖旧结果 |
| 暂停 | 暂停当前任务 | 正在生成的当前回复允许结束或进入安全等待，不再发送下一步 |
| 继续 | 从断点继续当前任务 | 先核对上一条消息状态，避免重复发送 |
| 重新 | 从第1步重新执行当前任务 | 先自动归档旧运行记录和已保存正文，再创建新 runId |

按钮始终显示，但根据状态启用/禁用：

- 未开始：开始可用；暂停、继续禁用；重新仅当存在历史运行记录时可用。
- 运行中：暂停可用；开始、继续禁用；重新可用但需要先安全暂停并归档。
- 已暂停：继续、重新可用；开始、暂停禁用。
- 已完成：重新可用；开始可用于新建一轮（仍需归档旧记录）；暂停、继续禁用。
- 需要处理：继续先执行安全恢复检查；重新会归档当前任务后从头开始。

“重新”与“＋新任务”含义区分：
- **重新**：复用当前任务设置，从第1步重跑，旧结果进入历史。
- **＋新任务**：创建新的任务实例，拥有独立配置、聊天窗口、图片、进度和结果。

## 五、点击平台卡片后，下面自动切换任务

### 点击规则

1. 用户点击 ChatGPT 方形卡片主体。
2. 系统检查 ChatGPT 的任务实例：
   - 如果只有一个正在运行，直接选中该任务。
   - 如果有多个正在运行，选择最近更新的运行任务，并在任务小方块区显示全部实例供精确切换。
   - 如果没有运行任务，优先选择最近暂停/待处理任务；否则选择最近使用任务。
3. `selectedInstance` 更新为目标任务 ID。
4. 任务设置标题、基础设置、模型、创作指令、图片关联自动载入该任务配置。
5. 进度卡、已保存内容、历史任务和运行日志全部切换为该任务数据。
6. 被切换走的平台任务继续在后台运行，不因页面选择变化而暂停。

### 点击事件实现要求

- `.platform-card` 或 `.platform-group` 主体绑定 `selectPlatform(platform)`。
- 任务小方块绑定 `selectInstance(instanceId)`。
- 开始/暂停/继续/重新/设置等按钮必须阻止事件冒泡。
- 卡片选中状态增加清晰的薄荷绿边框和浅色背景。
- 键盘可通过 Enter/Space 选择卡片，按钮有可见焦点样式。

## 六、任务设置区域重新排版

### 顶部：当前平台与任务选择

显示当前平台名称、任务名称和状态。下方用小方块显示该平台所有任务：

```text
ChatGPT · 任务设置                 运行中
[任务 A  12/30] [任务 B  4/10] [＋ 新任务]
```

- 每个任务小方块显示：任务简称、运行状态、完成数/总数。
- 点击任务小方块即切换编辑区和右侧运行数据。
- “＋ 新任务”是一个固定尺寸的小方块，点击后创建新实例，自动分配独立聊天窗口；创建后自动选中该任务。
- 新建任务只创建草稿和窗口，不自动开始，避免误触产生消耗。
- 新任务数量不再写死为 A/B；实例 ID 使用稳定唯一 ID，显示名称按任务A、任务B、任务C……自动编号。

### 设置区分为五组

1. **基础设置**：任务名称、任务方式、生成数量。放在第一屏，两个或三个字段横向排列。
2. **模型设置**：模型、工作模式、刷新模型。模型锁定等低频选项放进“模型高级设置”。
3. **创作指令**：第一次发送和自动续发内容，保持两个大输入框，不改变其功能。
4. **图片附件**：首轮图片与续写图片分别放在对应指令下方；保留加号、多图拖入和缩略图删除。
5. **其他设置**：窗口绑定、新聊天策略、续写是否重复发送图片、自定义多轮聊天方式、超时与选择器。默认折叠。

设置自动保存，不要求用户每次再点击保存。保留现有保存按钮作为可选手动保存，但弱化视觉权重。

## 七、并发与任务管理规则

- 固定 `MAX_CONCURRENT = 3`，不再提供顶部并发选择框。
- 可以保存多个任务实例；最多 3 个任务同时处于 running。
- 第4个及之后点击开始的任务进入 `queued`（等待）状态，不报错、不覆盖其他任务。
- 任一运行任务完成或暂停后，调度器自动从等待队列取下一个任务启动。
- 平台卡显示当前被选中的或优先级最高的活动任务摘要；若有多个任务，任务小方块显示各自状态。
- 任务总数、等待数、运行数可显示在“AI平台运行状态”标题右侧的小字中，不再新增一条顶部控制栏。
- 全局批量开始/暂停/新任务按钮全部移除；每个平台和每个任务实例独立操作。

### 数据迁移

- 现有 `chatgpt-A`、`chatgpt-B` 等任务迁移成新的动态实例记录，旧结果不删除。
- 旧标签页绑定关系保留。
- 历史任务、图片 ID、模型偏好、运行日志继续关联原任务 ID。
- 首次升级时生成迁移备份；迁移失败则回退旧数据，不允许清空原数据。

## 十、推荐最终使用方式

1. 点击上方 ChatGPT 方形卡，自动进入 ChatGPT 当前任务。
2. 在任务设置中选择任务 A 或任务 B，或者点“＋ 新任务”。
3. 填写该任务自己的提示词、模型和图片。
4. 回到上方平台卡，点击开始。
5. 想切换到豆包时，直接点击豆包方形卡；下面自动显示豆包自己的任务设置、进度和保存结果。
6. 不同任务互不影响，最多同时运行 3 个；超过上限的任务自动等待。
