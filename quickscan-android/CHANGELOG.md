# 快递快扫 | 版本更新记录

## v0.12 | 2026-11-05
- 优化扫码进入速度：CODE128 快速连续 2 帧（至少 35ms）、ITF 连续 3 帧（至少 90ms）识别验证，保持中心位置、条码尺寸和跨帧位置一致要求。
- 强化去重：SQLite 数据库升级为 version 3；新库对 `batch_id,code` 建立**非空单号唯一索引**。新登记通过事务 `saveIfNew` 检查和原子插入，重复回调只保存一次。历史库如果已有重复记录，不会删除原记录/照片，事务仍阻止新增重复。
- 每次只加载 14 条近期扫码记录；输入搜索时可查看最多 100 条，减少扫码时的主线程布局计算。
- CameraX 保持最低拍照延迟模式，并将 JPEG 质量设为 82，以兼顾文件体积和面单可读性。
- 拍照成功后才语音播报“成功”，避免过早提示让用户移开面单导致拍错照片；拍照期间暂停下一件识别，保证照片对应单号。
- 保留原始 UI 布局、Excel「已结算」导出、批次、图片放大/分享/清理等功能。
- 提醒：无法绝对保证所有损坏面单零误读；数据库唯一性保证**同一批次完全相同单号**不会被重复存入。此 v0.12 采用独立调试安装包名，不会迁移旧版数据。


## v0.11 | 2026-11-05
- **无需手工确认**：通过多帧验证后自动登记单号、播报成功并自动拍照。
- 优化识别等待时间：CODE128 连续3帧且至少80ms；ITF 连续4帧且至少140ms。保留码型、长度、几何位置、跨帧位置一致性限制。
- 条码在取景框内持续存在时锁定本次识别，需移开再扫下一次；同号再扫显示重复，防止同张单号反复入库或误识别出不同编号。
- 查询及展示性能优化：数据库新增复合索引 `batch_id,code`，扫码列表只加载最近35条，批次数量改用 COUNT 查询。
- 扫码页规范化：统一白色栏、整齐工具图标、最新单号和状态、下面按顺序显示扫码记录与搜索栏；移除“确认登记”“重新识别”按钮。
- 已记录成功后立即语音提示，照片异步保存期间短暂暂停下一件识别，避免照片绑定错单号；如照片失败单号仍保留可补拍。
- **现实说明**：软件识别无法保证100%无误。相比 v0.10，速度更快但人工校验保护取消，使用时仍应抽检。不同测试版包名数据不自动互通。


## v0.10 | 2026-11-05
- 修复“某个快递条码被识别成多个不同单号并误登记”的核心风险。严格支持 CODE128 / ITF，拒绝二维码、EAN/UPC商品码及许多短码；加入中心扫描范围、尺寸、单号长度和至少连续8帧且跨400ms一致性验证。
- 新单号先显示为待确认，**人工核对并点击“确认登记并拍照”才写入数据库**，拍照成功后播报成功。错误候选可以丢弃重新扫描；同号复扫显示重复。
- 扫码界面参考用户给的快递扫码软件示例：上方大摄像头+淡绿色网格，下方简洁操作工具、最新编号、实时历史列表；移除单独查询底部导航，首页搜索可查全部批次，扫码页内可搜索本批末四位。
- 原先 Excel“仅导出加已结算不修改数据库备注”、M.d 日期批次、照片全选删除、照片放大分享等功能保留。
- v0.10 为独立测试包名，需手机真机复核识别率、性能和拍照一致性。


## v0.9 | 2026-11-05
- 完整明细 Excel 导出时，“备注”列自动加上「已结算」，仅在导出文件中处理，软件内部 SQLite 备注保持不变；仅单号 Excel 模式不变。
- 新建批次默认使用手机本地日期 `M.d`（如 10.4）；同名时提示使用原批次或创建 -2、-3 后缀的新批次。
- 扫码取景框移到上方，最新单号在取景框下方；拍照、补光、录入、记录缩为图标。
- 每次识别到新的有效非重复快递单号，立即创建记录并自动拍照；去掉“自动拍照”的可选勾选框。
- 拍照期间暂停识别新单号，拍照结果绑定对应的记录 ID；失败时保留单号并显示照片未保存。
- 自动拍照性能与手机实际兼容性仍需真机测试；v0.9 使用独立安装 ID 避免覆盖旧 debug 包，数据不迁移。
